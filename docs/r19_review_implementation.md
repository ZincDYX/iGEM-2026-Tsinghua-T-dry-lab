## Execution boundary

Scientific numerical tests and author regression run only on the designated
compute environment, not on the desktop machine. Software protocol, UI and
packaging tests may run locally. Synthetic fixture values are never delivered
as project physical parameters or wet-lab observations.

No new Agent framework, runtime platform, guessed physical parameters or
alternative scientific tool has been introduced in the initial safety batch.

are explicitly not project biological data. Full original author/scientific

passed 41 tests. Frontend: 58 tests passed and TypeScript compilation passed.

The real auxiliary FASTA contains `ER_anchor_FUSn_SH3x3_PDZ_FTH1` (888 aa).

against all 888 original residues and its paired confidence record. Whole-model
mean pLDDT spans 59.74–63.63, and anchor residues 2–73 span 62.24–67.60.
These are predicted confidence observations, not an experimental measurement
or permission to treat the flexible full assembly as a rigid validated cage.
Verification of all model/confidence pairs is retained separately; a successful prediction does
not establish ER side, intact anchor retention, 24-mer assembly, LLPS or
fusion enzymatic activity. The original full K25 Mpipi author run also finished
all 500,000,000 requested steps; this is an author-method reproduction, not
a simulation of this fusion.

## Runtime, uncertainty and software acceptance

The later frozen implementation passes the server-only full suite: **832
passed, 9 skipped**, plus **105 passed** in the selected real-tool environment
and **53 passed** against the installed wheel. These counts overlap and must
not be added as independent scientific validations. Skips remain reported in
the private XML evidence: all nine are FreeSASA-dependent checks absent from
the general review Python environment; they pass in the real-tool environment.
Scientific fixtures test methods, not project biology.
Frontend: **58 passed / 22 files**, TypeScript and production build passed.
Built-asset browser acceptance: **12 passed**, including scoped preparation,
real HTTP execution, current-run identity, cancel and offline scientific viewers.

The real JPred deployment check first exposed an old submit-only route: one
new job was accepted but not retrieved, so that task failed. The corrected
native runner retrieved that same new job without submitting another; native
sequence and secondary-structure files parsed successfully. The failed run
is retained, not rewritten as success. Submission-only routes are now rejected
before external execution. This diagnostic 20-aa result is not formal complete
M1 evidence and is not a prediction of the 888-aa ER construct.

Three alternating same-machine software profiles compared commit `635b5db`
with the updated code using the same API fixture and 30 cached project GETs.
Median of the three runs: startup 3.206→2.667 s; per-GET median 27.498→14.950
ms; per-run p95 median 38.687→39.986 ms (no tail-latency improvement claim);
working set 120.865→117.092 MB; private bytes 473.776→469.635 MB.
SQLite SELECTs remained 210; BEGIN/COMMIT pairs fell from 30 to zero.
The first updated run had slower median GET latency, so these measurements
do not establish a universal speedup. This is not a whole-desktop/WebView,
OS-cold-start, long-viewer or concurrent-scientific-load benchmark.

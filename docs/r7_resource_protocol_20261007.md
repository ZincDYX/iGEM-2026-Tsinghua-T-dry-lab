# r7 resource and comparison protocol acceptance

Scope: r6 PR C and PR E/R6-06. Display/read protocols only; no solver,
scientific formula, parameter approval or evidence grade was modified.

- Raw ZIP request bodies are streamed within 20 MB, 256 members, aggregate
  expanded-byte and free-disk budgets. Original member names are checked before
  Windows path normalization. Traversal, duplicate case-folded names, symlinks,
  encryption and ambiguous logical paths are rejected. Only newly owned staging
  paths can be cleaned up. Validation precedes atomic registration/grants.
- Binary attachments retain exact original bytes. PNG/JPEG previews decode
  within pixel/frame budgets and export pixels without original metadata.
  Untrusted SVG/HTML is not executed. Original downloads keep their existing
  authorization and disclosure boundary; no universal secret-free claim.
- Versioned resource, series and structure schemas generate TypeScript/AJV.
  Every read checks explicit project grant and original SHA before cache access.
  Series points are indexed by file ID + SHA + display schema; SQL pages return
  only requested points/registered columns, preserving null/zero and units.
- PDB/mmCIF coordinate projections exclude free-form notes/custom atom fields.
  Residue model/chain/auth number/insertion identity is retained. Dedicated
  hash-bound sidecars may register fusion/reference mappings, pocket membership
  and explicitly sourced pLDDT. References require a current project grant,
  byte hash and exact reference residue match. Full-fusion positions additionally
  require an authorized FASTA hash, unique sequence ID and matching amino acid. B-factor is never pLDDT.
- Lineage edges require server-owned parent run and exact frozen snapshot.
  Strangers are forbidden. Comparison is one paginated batch, aligned by
  stage/object key, not ordinal position; ambiguous duplicate keys are rejected.
  Text keys are locators, not build identity. Source artifact/hash/attempt,
  frozen sequence-derived build facts and the existing F3 comparison parser
  govern numerical eligibility. Conditions/units/context/build mismatches
  block numeric comparison. Missing values remain null; no automatic ranking.
- Changed constructs still require a separately reviewed design plan; this
  view does not approve varying factors or execute a finite-design scan.
  M1/M2/M3/M5 are descriptive comparisons, not newly defined F3 metrics.

The first selected software/parser group had 20 passes; later Windows filename
  and FASTA identity cases are included in final server acceptance. No solver is
  invoked in the local display/parser group.
Independent oracles cover byte/pixel/metadata identity, grant-before-cache,
tamper refusal, PDB/mmCIF model/chain/insertion, sealed source, hostile ZIP,
actual HTTP preview/save/download, reversed candidate ordering and exact
formal-contract positive/negative cases. The positive contract is an explicitly
synthetic parser sample, never biological evidence or a scientific regression.

Limitations: catalog discovery/structure sidecars still parse bounded originals
on first/read discovery; structure projections have a source/atom budget but no
incremental coordinate index. The series cache is not cross-run scientific reuse.
Native CSP, full server regression and release identity are reported separately.

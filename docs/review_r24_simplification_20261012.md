# r24：结果页简化、公式执行绑定与紫色主题

本记录对应 2026-10-11 的 r23 Results / formula execution review，实施和验收日期为 2026-10-12。它不表示原始生物学实验已经完成，也不表示所有第三方工具已获得授权。

## 本轮改变

| Review 要求 | 实施结果 |
|---|---|
| 删除重复工作区入口与默认左栏 | 只保留 Inputs / Workflow / Results 主导航；项目在顶部，运行版本在 Results；Assistant 默认收起，显式 Review 后展开提案；已完成 Jobs 收起。没有伪 Terminal。 |
| 紫色主色调 | 浅色主色为紫色，深色为淡紫色；保留错误、成功的语义颜色。 |
| 输入不要成为通用 schema 表单 | Biological data / Plan configuration 共用导入事务；一个对象表；只编辑当前选中的序列角色或构建对象。删除常驻全项目 JSON 和泛化参数创建表单。 |
| M1 不展示 144 个调度节点 | Results 展示科学汇总父对象，map 子任务留在 Jobs；有类型地读取 `items`，显示候选、决定、已算特征、缺项和依据。 |
| M2 不展示空指标和伪结构 | 缺数据时只呈现实际阻断原因、已有来源和补数据操作；不把参考 PDB 充当融合体结构，不生成空的几何指标表。 |
| M3 只保留主要招募量 | 默认展示 dense 总浓度、dilute 游离浓度和 dense 分数；比值单列。显示约三位有效数字，底层数据和导出不舍入。 |
| M4 默认有意义的目标曲线 | 实际记录目标 15 时优先选择其 dilute 浓度；Species / Phase / Quantity 分开选择。单位不兼容不能叠加同轴。原始数值表默认关闭，显式 Data 打开分页视图。 |
| 局部和整批状态分开 | E1 只呈现其已求解状态，E3 缺项只在 E3 显示，整批部分完成另外标明。一次合成标记不等于实验验证。 |
| 不堆叠后台 JSON | 删除普通 Results 的后台树与重复来源区；原始文件、完整输出、来源记录仍可从授权后端和导出获得。 |
| 参数只展示当前模块消费字段 | 使用原执行器的 requirements；Parameter / Value / Unit；派生量不可覆写，来源只读。来源选择只提供原 Registry 判断兼容且已审核的已有记录。修改创建未批准的新版本，不覆盖旧记录或历史运行。 |
| 公式显示与执行同一事实源 | 正式原方法只读；Edit method 创建新版本和差异。可执行标量公式的预览由同一受限 AST 生成，不能用独立 LaTeX 伪装执行内容。 |
| 输出目录不是输入依赖 | 输出目录在输入路径校验前移出；真实输入依赖缺失、越界路径仍拒绝，未放宽目录权限。 |
| Tools / Plugins / Skills 简化 | 一个实际工具列表；真实预测 Run 绑定已导入序列，正常 Review / Accept / Start。未配置、配置未验证、真实输出成功和失败分开。插件仅显示用途、来源、版本、必要权限和状态。Skills 只需名称与指令，保留 Markdown 导入导出，不授予工具执行权限。 |
| 清理旧模式 | 删除旧 Scientist / Developer 用户入口及过时界面断言；保留真实行为、不可变历史和数值对照测试。没有新增计算引擎、第二调度器或模型权重。 |

复杂科学模块仍需要在 Workflow 中绑定其真实输入，不把“注册了一项能力”冒充“该能力已经有可执行数据”。安装、运行、构建与依赖锁定以根目录 [README](../README.md) 为单一说明，不再复制第二套安装流程。

## 大小、性能与交付边界

主入口 JS gzip 从此前约 107.32 kB 降至约 103.65 kB。Plotly 与真实 3D 仍按需加载。没有通过删除真实科学功能、降低求解精度或重复引入依赖来缩小软件。

桌面版仍包含独立 Python 和现有锁定依赖，不能把几 kB 的入口删减说成整个 EXE 大幅瘦身。真实浏览器完成资源循环与正常交互检查；没有系统 CPU / 内存基准，也不保证所有硬件都更快。

新 portable release 为 `FusionLab-Windows-20261012-r24-purple`：需解压并保留整个文件夹，不可单独复制 EXE。默认本地，不包含实验室服务器地址、模型身份或凭据。资源清单 / 源码快照 / ZIP 字节一致性及原生启动、认证、重开和子进程回收另行机械验收。源码、锁定依赖、Apache-2.0 LICENSE 保留；EXE 不替代正式仓库源码。

最终原生截图还发现新项目尚未保存时查询未完成导入，误报恢复失败。已使用现有 saved-project 身份判断是否查询，不把草稿修订号当持久化证据；真正的已保存项目恢复失败仍显示错误。增加两项回归检查，导入时首次保存不会重置当前预览。

最后一轮并行编译/浏览器出现 Windows 明确的 Out of memory、浏览器 ERR_INSUFFICIENT_RESOURCES 和导入请求 Failed to fetch；该轮不计通过。编译结束后同版本、同断言串行重跑，7 项安装版浏览器检查全部通过，未增加重试或放宽条件。这是资源压力下的验收记录，不是正式内存基准，也不据此证明不存在任何内存问题。

IUPred 实测使用已安装的 [saezlab IUPred 打包版](https://github.com/saezlab/iupred)，0.1.2 是其 Python 包版本，执行 `iupred(sequence, mode='long')` 的 IUPred2 路线，不是 AIUPred 或自行设计的替代模型。原始工具输出及执行来源留在私有后端证据中；包本身不随本桌面 release 分发。

仍需要外部条件：SignalP / DeepTMHMM / TANGO / PASTA 合法访问；真实融合体模型、完整置信度/残基映射与必要实验、运输和 ER 参数；模型服务的 function-call parser 配置；官方 GitLab 匹配的 CI Runner。缺少这些时不能宣称完整生物学流程、湿实验验证、所有真实工具作业、CI 或 Best Software 已全部达标。
